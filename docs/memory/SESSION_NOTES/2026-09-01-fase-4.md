## Qué se hizo

**Contrato** (`connectors/base.py`): `ToolSpec`, `CallContext`, `ToolResult`,
`BaseConnector`, más `CircuitBreaker` y el helper `guard` por el que pasa todo el I/O
externo. Los tres defaults van a la dirección segura: `autonomy_min=A2`,
`ToolResult.classification=C4`, y `health()` que debe sondear de verdad.

**Registry** (`connectors/registry.py`): descubrimiento por entry points, allowlist glob
por tenant, comprobación de salud con TTL, y la doble verificación —al construir el
catálogo y justo antes de invocar—. El catálogo es **por petición**, porque depende del
techo del solicitante y de qué conectores están sanos ahora.

**Conectores**: cliente MCP multi-transporte, n8n con correlación de callbacks,
OpenConnector dirigido por spec OpenAPI, cuatro drivers de base de datos con plantillas
allowlisted, y `repo_graph.query`.

**Generador** (`scripts/new_connector.py`): módulo, entry point, test de contrato y fila
de documentación. Lo generado pasa lint y sus propios tests antes de editar nada.

## Cuatro bugs reales, tres de ellos sólo visibles contra el servidor real

### 1. MCP 2.x renombró `inputSchema` a `input_schema`
Todo descubrimiento de tools fallaba con `AttributeError` dentro de un `TaskGroup`. Un
mock del `ClientSession` habría pasado sin protestar.

### 2. …y `isError` a `is_error`
Peor que el anterior: **un fallo remoto se reportaba como éxito**. Es exactamente la clase
de defecto que hace que el agente afirme haber hecho algo que no hizo. Ahora se comprueban
ambos nombres, porque un gateway puede correr cualquiera de las dos generaciones del SDK.

### 3. El log de fallo decía sólo `ExceptionGroup`
Los transportes MCP corren dentro de task groups, así que un fallo de conexión llega
envuelto. Registrar el nombre de la clase no le dice nada a nadie. Se añadió `describe()`,
que aplana la cadena; fue lo que hizo visible el bug 1 en un intento.

### 4. Una tool desconocida pausaba para aprobación humana
Si el descriptor no estaba en el catálogo, el nivel requerido se calculaba como A4 y el
grafo llamaba a `interrupt()`. Es decir: le pedía a una persona que autorizara una
herramienta que no existe, y si la aprobaba, fallaba igual. Ahora se rechaza directamente
y el rechazo llega al modelo, que necesita saber que la acción no ocurrió.

## Una nota de entorno

En Windows los subprocesos stdio necesitan el `ProactorEventLoop` mientras `psycopg`
exige el `SelectorEventLoop`, y la suite corre sobre el segundo. El test del transporte
stdio se salta en Windows con esa razón explícita; el de streamable HTTP —que es el
transporte que un gateway realmente ofrece— corre en todas partes, y CI en Linux ejecuta
ambos.
