# 2026-09-01 · Fase 1 · Núcleo agéntico + canal base

## Qué se hizo

**Kernel de dominio** (`core/`): `errors.py` con códigos estables, `classification.py`
(C0–C4 como `IntEnum` para que "¿supera el techo?" sea una comparación),
`autonomy.py` (A0–A4 + `AutonomyMap`), `state.py` (`AgentState` con reductores para
mensajes, citas y decisiones), `prompts.py` (registry versionado con validación de
variables al cargar), `checkpointer.py` (Postgres/Redis/memoria + namespacing de
`thread_id` por tenant e instancia), `hitl.py`, `router.py`, `planner.py` y `graph.py`.

**Grafo**: `intake → governance_gate → planner → domain_subgraph → tools → synthesis →
quality_gate → respond`, con reentrada `quality_gate → planner` para `retry`/`replan` y
corte `governance_gate → respond` cuando se bloquea.

**Subgrafos**: `generalist` (recuperación + síntesis, cero dominio) e `it_support`
(detección de intención, guía por tipo de petición, y etiquetado de categoría de acción
para que el mapa de autonomía la encuentre). El contrato `DomainSubgraph` **no importa
LangGraph**: es la mitigación de lock-in que prometía el ADR-001.

**Gateway de modelos**: `model_policy.py` como punto único de decisión de backend, y
`GovernedGateway` como única forma de alcanzar un transporte. El transporte habla con el
proxy LiteLLM por HTTP en lugar de importar el SDK, lo que mantiene la imagen de
`agent-api` sin SDKs de proveedores.

**Perfil**: modelo Pydantic completo con `extra="forbid"`, expansión de `${VAR}` que
falla si la variable no existe, y validadores cruzados (HITL sin grupo de aprobadores,
CAG sin RAG, célula sin ninguna superficie de entrada).

**API**: canal OpenAI-compatible con SSE, `/v1/models`, `/admin/{config,approvals,tasks,
memory}`, `/health/{live,ready}` con reporte por dependencia y por capacidad instalada.

**Despliegue**: Dockerfile multi-stage (api sin torch, worker con `knowledge`),
`docker-compose.yml` con siete perfiles, override de GPU para vLLM, y configuración de
otel-collector, Prometheus, Loki y Grafana.

## Bugs reales encontrados (y arreglados)

1. **Nodos del grafo con `lambda`.** LangGraph decide si esperar un nodo con
   `iscoroutinefunction`; una lambda que devuelve una corrutina falla con
   `InvalidUpdateError`. Se usa `functools.partial`, que sí se detecta como asíncrona.
2. **Autonomía concedida vs. requerida.** Estaban conflacionadas: `resolve()` combina por
   **máximo**, correcto para el *requisito* de una acción, pero eso hacía imposible que
   un techo A0 (usuario anónimo) redujera nada. Se separaron las dos cantidades y la
   regla quedó explícita: se ejecuta sin humano sólo si `requerido < A2 Y requerido <=
   concedido`. Sin esa separación, un solicitante anónimo podía ejecutar acciones A1.
   Documentado en `docs/GOVERNANCE.md` §4 y con test de regresión.
3. **`escalate` se marcaba como `completed`.** El nodo `respond` sobrescribía el estado
   sin mirarlo, así que una tarea escalada a un humano se reportaba como terminada.
4. **`add_logger_name` con `PrintLoggerFactory`.** Rompía el arranque: ese procesador lee
   `logger.name`, que sólo existe en loggers de stdlib. El nombre se enlaza como campo.
5. **La pausa del grafo no llegaba a la cola de aprobaciones.** El grafo se suspendía
   correctamente pero `/admin/approvals` no mostraba nada: nadie podía aprobar. El canal
   traduce ahora el `__interrupt__` a una entrada de cola.
6. **`docs_check` marcaba "todo" como placeholder.** `\bTODO\b` con `IGNORECASE` sobre
   documentación en español. Además, los marcadores dentro de código en línea son
   *referencias* (una regla que prohíbe `TODO`), no marcadores. Ambos con test.
7. **Etiquetas de imagen inventadas.** Siete de las quince imágenes de Compose no
   existían con la etiqueta que había escrito. Se verificaron todas contra los registros
   reales (Docker Hub y GHCR).

## Notas de entorno

* `psycopg` (que usa `langgraph-checkpoint-postgres`) necesita la rueda binaria: añadido
  `psycopg[binary,pool]`. En Windows además exige el `SelectorEventLoop`; resuelto en
  `tests/conftest.py` y documentado en `RUNBOOK.md` §7.
* Los comandos de shell por encima de ~6 KB llegan truncados en este entorno; los
  archivos grandes se escriben con la herramienta de escritura directa.
